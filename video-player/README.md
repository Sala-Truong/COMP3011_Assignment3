# COMP3011 Assignment 3 – Concurrent Video Player with AI Subtitles

## 1. Project Overview

This project extends the multithreaded video player from Assignment 2 by adding automatically generated subtitles during video playback.

The main goal was to integrate a cloud-based speech-to-text service with the existing JavaFX video player while keeping video and audio playback smooth.

The application consists of two parts:

- **Video Player:** A JavaFX desktop application responsible for video playback, audio, frame processing, controls, and subtitle display.
- **Subtitle Server:** A Spring Boot application that receives extracted audio and uses OpenAI's Whisper API to generate transcription text and timing information.

I reused and extended my previous Assignment 1 and Assignment 2 work rather than building a completely separate application.

One of the biggest challenges was making subtitles work without slowing down the video player. I also spent time improving caption synchronization, especially when seeking or starting playback.

## 4. How to Run

### Requirements

Before running the application, make sure Java 25 and Maven are installed.

An active OpenAI API key is required to generate new subtitles. The video player can still play videos when the subtitle service is unavailable.

### Step 1: Configure the API key

In a terminal, set the `OPENAI_API_KEY` environment variable before starting the subtitle server.

```bash
export OPENAI_API_KEY="YOUR_API_KEY"
```

Replace the placeholder with a valid key.

The API key should be stored securely and must not be committed to Git or included in the submission archive.

### Step 2: Start the subtitle server

Open a terminal in the `subtitle-server` directory:

```bash
./mvnw spring-boot:run
```

The subtitle API is available at:

```text
http://localhost:8080/api/v1/subtitles
```

Keep the server running while testing the player.

### Step 3: Run the video player

Open another terminal in the `video-player` directory.

Run with audio and subtitles:

```bash
mvn javafx:run '-Djavafx.args=-aS test-video.mp4'
```

Run with audio but without subtitles initially enabled:

```bash
mvn javafx:run '-Djavafx.args=-a test-video.mp4'
```

Run with additional video effects:

```bash
mvn javafx:run '-Djavafx.args=-aSjfddn test-video.mp4'
```

The video path can be replaced with another supported media file.

The `-S` option enables subtitles initially. Subtitles can also be toggled while the video is playing.

## 5. Implementation

### 5.1 Video Playback and Concurrency

The video player is based on the Model-View-Controller architecture from Assignment 2.

The model manages decoding, frame processing, buffering, and playback state. The controller handles user interactions, while the view displays the video and playback controls.

The player uses background worker threads for frame processing instead of performing all processing directly on the JavaFX application thread.

This is important because video decoding and visual effects can take time. If too much work is performed on the UI thread, playback can become unresponsive.

I retained the multithreaded processing approach from Assignment 2 while integrating the new subtitle functionality.

### 5.2 Subtitle Generation

I implemented the subtitle client to communicate with the Spring Boot backend.

The general process is:

1. Extract audio from the video using FFmpeg.
2. Divide the audio into smaller chunks.
3. Send each chunk to the subtitle server through an HTTP request.
4. Use the backend to request a transcription from OpenAI Whisper.
5. Receive text with word-level and segment-level timestamps.
6. Format the transcription into readable captions.
7. Display captions according to the current video playback time.

I used audio chunks of approximately 20 seconds and started requesting upcoming chunks before reaching the end of the current one.

This approach avoids having to transcribe the entire video before playback can begin.

Subtitle requests are performed in the background so that network delays do not directly block video playback.

### 5.3 Subtitle Display and Synchronization

The player uses the current media playback time to determine which subtitle should be displayed.

Captions are shown near the bottom of the video using white text and a dark translucent background to improve readability.

During development, I initially used more expensive text rendering with outlines. Although this made the subtitles visible, playback became less smooth when captions appeared.

I changed the rendering approach to use a lightweight JavaFX `Label`, enabled caching, and avoided repeatedly updating the label when its text had not changed.

This made a noticeable difference in local playback testing.

I also encountered a synchronization issue where some captions appeared slightly earlier than the spoken dialogue.

I investigated the timestamps returned by Whisper and adjusted the handling of the initial caption when the timestamp information indicated an unusually early start.

The current implementation uses a JavaFX overlay for subtitle presentation rather than drawing the caption directly into each processed video frame. This was a deliberate performance trade-off. It keeps subtitle rendering separate from video effects, although it means the text itself does not pass through the existing frame-effect pipeline.

### 5.4 Subtitle Controls

I added a subtitle toggle button to the player interface.

Subtitles can be enabled or disabled using either:

- The CC button in the player
- The `S` key on the keyboard

When subtitles are disabled, the text disappears without stopping playback.

The player also updates the displayed caption according to the new playback position after seeking.

### 5.5 Error Handling

I wanted the subtitle feature to be optional from the playback perspective. A network problem should not make the video itself unusable.

If the subtitle server cannot be reached or an API request fails, the player reports that subtitles are unavailable while allowing video and audio playback to continue.

During testing, I encountered an HTTP 500 error that was caused by an invalidated OpenAI API key. Checking the Spring Boot logs helped identify the actual authentication issue.

I resolved it by updating the API key configuration rather than making unnecessary changes to the video playback code.

This was a useful debugging experience because the error appeared in the JavaFX player, but the underlying problem was in an external API request.

## 7. Challenges and Decisions

There were several issues that required extra investigation during development.

**Keeping video playback smooth**

This was probably the most noticeable issue while working on subtitles. The video played smoothly without captions, but displaying captions initially introduced some stuttering.

Instead of changing the whole decoding system, I investigated the JavaFX rendering overhead and reduced the amount of work required to display subtitle text.

**Matching subtitles with dialogue**

The timestamps returned by the transcription service were not always a perfect match for the audio. I checked the actual playback against the returned word and segment timings instead of applying a large global delay to every caption.

**Handling external service failures**

A successful HTTP connection to the backend does not guarantee that the OpenAI request will succeed. I learned to inspect both the client-side error and the Spring Boot logs before deciding where to make changes.

**Balancing performance and complexity**

I chose to use background audio extraction, asynchronous subtitle requests, and a lightweight caption overlay.

These decisions helped keep the subtitle implementation manageable without unnecessarily changing the working frame-processing architecture.

## 8. Known Limitations

There are still some areas that could be improved:

- Subtitle accuracy depends on the audio quality and the timestamps returned by Whisper.
- A new audio chunk may take time to transcribe, depending on network and API response time.
- The current subtitle overlay is separate from the frame-effect pipeline, so visual effects are not applied directly to the subtitle text.
- The initial-caption timing adjustment is a heuristic and may not behave equally well with every video.
- Further testing with unfamiliar media, heavy combinations of effects, and media removal would help establish reliability beyond the current local tests.
- Server-side caching could be extended to reduce repeated transcription requests and improve the experience when replaying previously viewed media.

These are trade-offs I would consider if I continued developing the application.

## 9. What I Learned

This assignment helped me understand how different parts of an application need to work together, especially when concurrency and cloud services are involved.

The most useful part was learning to identify where a problem was actually happening. A video glitch could come from decoding, thread scheduling, or JavaFX rendering, while a subtitle failure could come from the network, backend, or external API.

I also learned that getting a feature to work is only part of the task. It is important to test how the new feature affects the rest of the application.

Rather than rewriting the project whenever an issue appeared, I tried to isolate the problem, make a smaller change, and test again.

The final result is a working extension of my previous video player with automatic subtitle generation, playback controls, and continued playback when the subtitle service is unavailable.
